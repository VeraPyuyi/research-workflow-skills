# Prepare Submission, Rebuttal and Revision

Read the [shared contract](../research-navigate/references/workflow-contract.md)
and relevant [domain references](../research-navigate/references/domains/index.md).
Use [model routing](../research-navigate/references/model-routing.md) for native
requirements/rebuttal preparation and an independent evidence review.

## Establish the venue profile

For a full-paper Goal, this preparation can run before writing or blind review.
Record venue/year/track, authoritative requirements and reviewer criteria with
actual inspection dates. Classify artifact/reproduction requirements as required
at submission, recommended, after acceptance or optional artifact evaluation.
Use this profile for M4/M5; do not give reviewer agents internal decision records.
If the venue is undecided or a requirement is unverified, continue supported
preparation without claiming venue-specific submission readiness.

The requested reproduction package remains a deliverable even when artifact
evaluation is optional. Include applicable code/environment, configurations,
data access/instructions, execution steps, run records and result-to-figure mapping.
Run acceptance checks required by the profile and the approved completion contract,
recording actual commands/results and untested scope. Do not impose full training
reruns just because a venue recommends code availability.

## Assemble the actual candidate

1. Identify target venue/track, manuscript revision, authors, attachments and
   existing authorization. Inspect the final files and unresolved scientific
   review items rather than assuming a draft is submission-ready.
2. Verify current requirements from the venue's authoritative material: relevant
   deadline/timezone, format/limits, anonymity, declarations/disclosures, artifact
   rules and submission mechanics. Record source and inspection date. If access
   is unavailable, label unverified requirements and prepare only supported parts.
3. Check consistency across manuscript, metadata, authorship, references, appendix
   and code/data statements. Verify document build/render when applicable.
   Apply the [submission leakage audit](../research-review/references/submission-leakage.md)
   to the exact deliverable bytes, including nested reproduction archives, hidden
   metadata, local path keys and stray agent content. Unresolved private information
   or required uninspected surfaces prevent submission readiness. Infrastructure
   placeholders are allowed; required scientific content and disclosures stay truthful.
4. Produce a candidate manifest and readiness report, with verified checks and
   unresolved blockers. A materially changed claim, author list, destination or
   attachment requires the affected decision; routine edits within authority do not.
   For a full paper, complete M5 with the second fresh-context venue review and
   at least 8/10 from every assigned final reviewer plus final build/reproduction acceptance; reuse valid earlier scientific coverage
   instead of launching an automatic third full review at packaging.
   Complete the submission/release review gate on the actual package before any
   external submission. Record reviewers, checked scope and unresolved findings;
   a passed internal review is not submission authorization.
5. Perform an external submission only when explicit authorization covers the
   actual action, target and materially matching candidate. Reuse valid existing
   authorization. Capture receipt/version/status when the supported action succeeds.

## Rebuttal and revision

Use actual reviewer/editor comments. Map each to evidence, a response, manuscript
changes and any necessary experiment. Distinguish completed work from commitments.
Route substantive research changes back to the relevant stage and budget review;
do not fabricate reviewer feedback, results or agreement.

## Deliver and finish

Deliver the submission/revision package, requirements checklist with sources,
comment-response matrix where relevant, candidate manifest, approval/action status
and shared handoff. An unavailable submission tool yields a ready-for-user package,
not a claimed submission.
Keep simulated review/author response records separate from actual editor feedback
and from public attachments unless explicitly intended. Full-paper Goal completion
requires the actual final paper, reproduction package and applicable verified
checks, not an upload receipt. Missing required evidence, failed acceptance checks
or exhausted allowance leave a partial outcome, never a completed-paper claim.

Example: approval of one manuscript does not cover a revision that adds an
unsupported central claim; prepare the comparison and resolve that change before
using the old submission authority.

# Allowance and live routing evidence

Live availability is a dated observation, not a permanent capability. Refresh the
account's applicable allowance before dispatch; a quota limit, enabled billing,
cached model catalog, or historical success does not prove existing credit.
Record unit, covered models, expiry, pending work and usage reconciliation.
Unverified coverage means prepare the task and continue independent work.

## Bounded functional checks

For the approved 2026-10-24 validation, the ceiling was four initial external
requests (two native Jev primitives requests, one Cursor, one Vertex), with at
most one repair retest per channel and seven total. This was a functional check,
not a model ranking. Future budgets come from the current project's authority.

Use direct endpoints with empty provider fallback, a stable request ID and a
durable pre-submission reservation. Record submitted state before transmitting.
An unknown completion retains the reservation until reconciled; do not resend
because a client timed out. Do not resample a disappointing answer. Set a hard
output cap where the actual upstream supports it; an accepted request field
alone does not establish enforcement.

## Observations and implications

- Cursor Plus covered its own models with medium effort and Fast off according
  to the official plan documentation and a refreshed subscription observation.
  Its separately reported on-demand balance was excluded.
- A Composer 2.5 request returned correct code, but the gateway recorded xhigh
  after medium was requested. Research strict dispatch is blocked for this
  endpoint until the adapter/account mismatch is reconciled. Do not label this
  as a verified medium route or force a synthetic unsupported effort.
- The Cursor adapter did not enforce the requested output-token limit in the
  observed response accounting. A task that requires a hard generation-cost
  ceiling must use another covered endpoint with verified enforcement.
- Jev and Vertex had no configured balance endpoint. Their official account
  pages required sign-in. Native Jev Choice/Score/Noul therefore remain covered
  by offline validation, with live allowance and primitive checks pending.
- Vertex application credentials matched the configured quota project locally;
  this does not establish applicable remaining credits.

Request model, gateway-sent model, response-reported model, effort and billing
evidence are separate fields. Preserve disagreements. An adapter may echo a
model ID, so record the evidence level rather than asserting upstream identity
from the echo alone.

Credential contents and raw account logs remain local. The portable release
contains only sanitized evidence. The detailed release report lives in the
repository's `docs/release-validation.md`.
